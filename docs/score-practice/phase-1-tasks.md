# 第 1 期任务：时间轴与双手乐谱骨架

## 范围

这一期只做“可运行的底座”，不追求完整练习体验。

## 任务拆分

### 1. 建立文档和目录约定

- 新增 `docs/score-practice/`
- 统一后续设计文档和实现 checklist 的存放方式
- 在实现代码前先约定数据对象名字，避免边写边频繁改名

### 2. 梳理现有 MIDI 输入链路

- 复用 `src/core/midi/unified.py` 中已有的归一化能力
- 明确当前前端能拿到哪些字段
- 明确当前缺失项：
  - 按住过程的连续力度变化
  - 稳定的左右手识别
  - 完整的乐谱对象

### 3. 新建乐谱数据模型

- 定义 `ScoreSong`
- 定义 `ScoreNote`
- 定义 `PracticeSession`
- 定义 `PerformedNote`
- 保持模型独立于具体 UI

### 4. 固定速度时间换算

- 支持 `4/4`
- 支持固定 `4 拍 = X 秒`
- 提供 `tick <-> ms` 的换算方法
- 先不做变速

### 5. 双手乐谱录入方式

- 先选一个简单可手写的数据格式
- 每个音必须带 `hand`
- 左右手音符可以同时落在同一 tick
- 先支持休止段为空，不单独建复杂休止对象

### 6. 运行时当前状态查询

- 实现“当前 tick 对应哪些目标音”
- 实现“当前有哪些键处于按下状态”
- 输出左手/右手当前目标集合

### 7. 最小双谱表展示

- 复用现有 VexFlow / Bravura 基础
- 能把左右手目标音分别放到高音谱号和低音谱号
- 先支持简单时值，不急着把所有连线和装饰做全

## 粗略 TODO：匹配规则

第 1 期先记 TODO，不做严格实现：

- 一个 `ScoreNote` 是否只允许匹配一个 `PerformedNote`
- 如果用户按了一半松开，再补按，是否允许匹配多个片段
- 同音重复快速敲击时，归属给前一个目标音还是后一个目标音
- 左右手同音时，如何判定归属
- 休止区误按算全局错误还是挂到最近目标音上

建议做法：

- 第 1 期只记录足够的原始信息
- 第 2 期再正式实现第一版匹配器

## 交付结果

这一期结束时，项目至少应该能回答下面的问题：

- 一段 16 拍的目标曲谱在内部是如何表达的
- 左手和右手的目标音如何同时存在
- 点击开始后，当前时间点应该按什么
- 当前实际按下了什么

如果以上四点能稳定跑通，第 2 期再进入判定和可视化反馈。
