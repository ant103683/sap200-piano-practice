# 第 2 期任务：判定引擎与进度条反馈

## 范围

这一期重点是把“练习系统”真正做起来，而不是继续扩数据模型。

## 任务拆分

### 1. 建立判定结果对象

- 定义 `JudgmentResult`
- 定义 `ErrorSegment`
- 定义 `ExtraNoteJudgment`
- 确保结果对象不反向污染原始乐谱和原始演奏数据

### 2. 做第一版匹配器

- 输入：`ScoreNote[]` + `PerformedNote[]`
- 输出：`JudgmentResult[]` + `ExtraNoteJudgment[]`
- 先只处理固定速度和固定拍号

### 3. 做第一版时间窗策略

- 每个目标音生成一个匹配窗口
- 允许轻微提前和轻微延后
- 同音候选按距离排序
- 先不做复杂机器学习式打分

### 4. 做细进度条视图

- 每个目标音渲染一条目标条
- 根据 `errorSegments` 叠加实际覆盖
- 同音跨拍目标要显示为一条连续长条
- 中间断开要能明显看出来

### 5. 接入左右手分区

- 左手区域单独显示
- 右手区域单独显示
- 双手同步滚动或同步游标
- 至少要能一眼看出哪只手出问题

### 6. 增加错误显示

- 休止区误按能显示
- 错误音高能显示
- 显示方式以“轻提示”为主，不要把整个界面染红

## 粗略 TODO：匹配规则细化

以下先写进 TODO，等第 2 期中后段再收敛：

- 同一个目标音最多允许匹配几个实际片段
- 匹配窗口是固定值还是随时值缩放
- 两个相邻同音目标之间，边界如何切分
- 左右手同音同时间时，是否需要手别强约束
- 提前按下但刚好延续覆盖目标区间，算早按还是可接受

## 交付结果

这一期结束时，至少要满足：

- 一个目标音符能生成可读的判定结果
- 一个长音中断后，界面能看出断点
- 左右手可以分别看到练习进度
- 误按音不会完全消失
